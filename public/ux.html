01
Case Study

AI 콜센터 상담사 트레이닝 서비스

상담사가 AI 가상 고객과 롤플레잉하며 스스로 훈련하는 게임형 트레이닝 서비스. 관리자의 운영 부담은 줄이고, 상담사는 게임처럼 스스로 훈련합니다.

서비스 기획프로덕트 재설계 게임화데이터 기반 기획AI 서비스
역할: 서비스 기획과 UX 설계 단독 (앱, 서버 개발자 협업)  |  0→1 기획, 사내 POC 완료
배경 — 왜 만들었나

보험 TM 상담사는 신입 온보딩과 거절 대응 훈련이 계속 필요하지만, 실제 고객으로 연습할 수 없고 사람 트레이너에 의존하면 리소스와 훈련 품질의 일관성에 한계가 있습니다. AI 가상 고객으로 언제든 반복 훈련할 수 있게 만들어, 훈련을 사람 없이 확장하고 상담 품질을 끌어올리는 것이 이 서비스의 목표였습니다.

Problem

AI 고객의 반응이 실제 고객과 달랐다

AI 고객이 매번 완결된 긴 문장으로 대답해서, 짧게 반응하는 실제 고객과 달라 상담사가 실전 감각을 익히기 어려웠습니다.

Insight — 문제 1 (훈련의 질)

실제 통화는 짧은 반응과 되묻기의 리듬

고객은 완성된 문장이 아니라 짧은 수신 확인과 되묻기로 반응했습니다. 문제는 말투 예시 부족이 아니라 생성 방식이 실제 통화와 반대라는 점이었고, 이 분석 결과로 AI의 발화 방식과 채점 기준을 실제 통화 리듬에 맞춰 재정의했습니다.

↓
재정의 — 문제 2 (훈련 참여)

질을 고쳐도, 참여가 없으면 소용없다

훈련 품질을 데이터로 해결한 뒤에도 또 다른 문제가 있었습니다. 관리자가 시나리오를 일일이 배포하는 방식은 관리 부담이 크고 상담사의 자발적 훈련을 막았습니다. 필요한 건 더 정교한 관리 도구가 아니라, 상담사가 스스로 플레이하는 구조였습니다.

↓
기획 결정

배포(push)를 없애고, 넛지(pull)로 재설계

관리자는 표준 대본을 고르고 고객을 자연어 한 칸으로 소개만 하면, 시나리오와 채점 기준은 시스템이 자동 생성합니다. 상담사는 레벨과 클리어율, 팀 리더보드로 스스로 훈련하고, 실전과 연습을 분리해 성적을 관리합니다. 관리자의 반복적인 운영 개입을 최소화하고, 상담사가 스스로 훈련하는 서비스 루프로 다시 설계했습니다.

Solution

게임형 훈련 루프와 자동화된 운영

게임형 훈련레벨, 클리어율, 별점으로 스스로 도전
실전 / 연습 분리실전은 기간이 열리는 회차로만
AI 고객 자동 생성대본 × 고객 소개 × 난이도
관리자 3걸음입력 → 확인 → 저장
자동 채점대본 체크포인트 + 거절 8종
넛지 운영스트릭, 데일리, 팀 리더보드
주요 기획 결정

배포를 넛지로

관리자가 매주 할당하는 LMS 방식을 버리고, 상담사가 스스로 플레이하는 구조로. 관리 부담을 없애고 자발적 훈련을 유도.

채점을 자동 생성

관리자가 미션과 가중치를 입력하던 방식을 폐지. 대본 체크포인트와 거절 정답지 8종으로 자동 채점하도록 설계.

실전과 연습 분리

연습은 상시 무제한, 실전은 기간이 열리는 회차로만. 두 성적이 섞이지 않게 계열을 분리.

콘텐츠 계층 설계

콜 유형 → 상품 → 대본 → 시나리오. 대본 하나로 고객만 바꿔 여러 시나리오를 만드는 1:N 구조.

공정한 지표 설계

난이도가 사람마다 자동으로 오르는 구조라 절대 점수 비교가 불가능해, 순위를 'Lv 평균 대비'로 매기고 개선폭을 (최근 − 첫 점수)로 정의했습니다.

평가와 실행을 한 화면에

별도 평가 화면 대신 통계 화면에 훈련 지정·알림 버튼을 심어, 약점을 보고 그 자리에서 처방하는 선순환 루프로 설계했습니다.

사용자 여정과 화면 흐름
정책과 프로세스 설계 — 임시 비밀번호 발급 흐름
가치와 배운점

사람의 반복적인 운영 개입을 줄이면서 훈련을 확장하고, 상담사의 거절 대응력과 상담 품질을 일관되게 끌어올릴 수 있는 구조를 만들었습니다. 관리자의 반복 개입 없이도 상담사의 자율 훈련이 도는 것을 사내 POC로 검증했습니다. 예쁜 화면을 만드는 것을 넘어, 서비스가 계속 쓰이도록 루프와 정책을 설계하는 것이 기획의 핵심이라는 것을 체감한 프로젝트입니다.

02
Case Study

KB증권 직원 업무 단말 개선

증권사 직원이 시세, 주문, 계좌를 빠르게 오가며 처리하는 통합 업무 단말(HTS 환경)을 재구축하며 화면과 업무 흐름을 개선했습니다. 잘못 누른 화면 하나가 주문 실수로 이어질 수 있는, 정확성과 속도가 모두 중요한 환경이었습니다.

업무 프로세스 기획AS-IS 분석 업무 플로우 개선금융 도메인
역할: 화면 설계 및 업무 흐름 개선 기획  |  동양시스템즈 (2022 – 2024)
Problem

기존 업무 화면은 기능과 정보가 여러 곳에 분산되어 있어, 사용자가 업무 흐름을 한눈에 따라가기 어려웠습니다.

My Role

생소한 증권 도메인과 새로운 개발 환경을 빠르게 익히며, 현업 요구사항과 기존 업무 흐름을 분석해 화면 및 시스템 요건을 정리하고, 실사용자(임직원) 피드백을 반영해 화면 구조와 업무 플로우를 다시 설계했습니다. 개발 및 협력 조직과 구축 과정에서 요구사항을 조율했습니다.

Result

계좌관리 파트에서 간단한 조회부터 차트까지 100개가 넘는 화면을 개선해, 정보 탐색과 반복 업무를 단순화하고 가독성과 운영 효율을 높였습니다. 매일 쓰이는 업무 도구에서 화면의 흐름이 곧 업무 속도가 된다는 것을 체감한 경험입니다.

화면 개선 — Before → After
Before
  • 정보가 여러 영역에 분산
  • 반복적인 화면 이동
  • 업무 흐름 파악이 어려움
→
After
  • 관련 정보를 한 화면에 통합
  • 주요 업무 순서에 맞춰 화면 재구성
  • 반복 작업 단계 축소

* 실제 화면이 아닌 구조 개념도입니다.

배운점

금융처럼 실수 비용이 큰 도메인에서는, 화면을 단순하게 만드는 것 자체가 리스크를 줄이는 기획이라는 것을 배웠습니다.

03
Case Study

FS-DS 사내 디자인 시스템

여러 부서가 공용으로 쓰는 웹 서비스 UI 표준을 단독으로 기획하고 구축해, 팀 전체가 일관된 화면을 만들도록 지원했습니다.

프로세스 표준화디자인 토큰 컴포넌트 설계다직군 협업
역할: 디자인 시스템 기획, 구축, 운영 단독  |  한일네트웍스 (2025 – 현재)
Problem

프로젝트마다 버튼, 입력창, 모달을 매번 새로 만들어 화면이 제각각이었고, 디자이너와 개발자가 같은 논의를 반복했습니다.

Solution

색상, 간격, 타이포를 디자인 토큰으로 체계화하고, 65개 컴포넌트를 일관된 구조로 설계했습니다. Storybook으로 사용법을 문서화하고 도입 부서마다 온보딩을 진행해 사내 표준으로 자리 잡게 했습니다.

디자인 토큰 체계

컬러, 간격, 타이포를 토큰으로 정리해, 한 곳만 바꿔도 전 화면이 일관되게 반응.

일관된 컴포넌트 구조

65개 컴포넌트를 같은 규칙으로 설계 — UI는 제공하고 로직은 소비자에게 위임해 어디서든 예측 가능하게.

Storybook 문서화

30여 개 컴포넌트를 라이브 프리뷰, 코드 복사와 함께 문서화해 설명 없이도 바로 사용.

다부서 온보딩, 표준 전파

2개 부서 4개 프로젝트에 도입 교육을 진행해 실제 제품에 적용, 추가 도입도 진행 중.

기획을 코드로 구현하고 운영까지 해봤기에, 개발 조직과 같은 언어로 대화하며 기획을 실제 제품으로 만들어낼 수 있습니다.

배운점

혼자 잘 만드는 것보다, 여러 부서가 실제로 쓰게 만드는 도입과 운영이 더 어렵고 중요하다는 것을 배웠습니다. 표준은 구축이 아니라 합의로 완성됩니다.
